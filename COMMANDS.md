# Дерево команд ChatDB SelfService

```
ChatDB Bot
│
├── 🟢 Базовые (все пользователи)
│   ├── /start          — регистрация/вход, привязка Telegram-аккаунта (новичку даётся роль DefaultUser)
│   ├── /weblogin       — одноразовый код входа в веб-интерфейс (живёт 5 минут)
│   ├── /whoami         — кто я (id, имя, все роли)
│   ├── /ping           — проверка, что бот жив
│   └── /help           — список доступных команд
│
├── 🌐 Веб-интерфейс (http://127.0.0.1:8000, тот же процесс и БД, что и бот)
│   ├── вход            — только код из бота (/weblogin); сессия 30 дней
│   ├── Дашборд         — кто я, счётчики, ближайшие срабатывания (24 ч)
│   ├── Подключения     — список (видимость по ролям), создать/изменить/проверить/вкл-выкл (Admin)
│   ├── Триггеры        — список, создать/изменить (одна форма вместо 7 шагов), проверить,
│   │                     вкл-выкл, удалить, расписание на сутки; управлять может автор или Admin.
│   │                     Проверка: результат показывается на странице И отправляется в Telegram
│   │                     (личный → в личку автору, групповой → в чат из настроек)
│   ├── Пользователи (Admin) — блокировка/разблокировка, присвоение/снятие ролей
│   └── Роли (Admin)    — создать, переименовать/описание, удалить (юзеры → DefaultUser)
│
├── ⚡ Триггеры (Выводится текущая роль пользователя, видны личные триггеры и все групповые триггеры, созданные пользователями этой роли. Admin видит все триггеры)
│   ├── /create_trigger — создание:
│   │      имя → подключение → тип (личный/групповой+чат: chat_id числом
│   │      или ссылка https://t.me/c/<id>/<топик> — уведомления уйдут в указанный топик)
│   │      → расписание → SQL → текст сообщения ($1, $2…) → подтверждение
│   ├── /edit_trigger — пошаговое изменение:
│   │      подключение / тип+чат / расписание / SQL / текст сообщения
│   ├── /check_trigger — проверить сейчас (карточка + результат; результат также
│   │      доставляется как при срабатывании: личный → в личку, групповой → в чат из настроек)
│   └── /delete_trigger — выбор + подтверждение
│
├── 👤 Пользователи (видит только Admin; сортировка: сначала active=True, затем по #id; по 5 на страницу; в заголовке выводится роль вызвавшего)
│   ├── /users                    — список (карточки с ролями, пагинация)
│   ├── /activate_user      — активировать (пошагово: выбор пользователя → подтверждение)
│   ├── /add_role    — присвоить роль (внутренняя; пошагово: пользователь → роль кнопками)
│   ├── /remove_role              — забрать роль (внутренняя, пошагово: пользователь → его роли кнопками или все сразу)
│   └── /deactivate_user    — деактивировать (пошагово: выбор пользователя → подтверждение)
│
├── 🔑 Роли (видит только Admin)
│   ├── /roles         — список ролей (описание, +сколько пользователей/подключений)
│   ├── /create_role   — создать роль (2 шага: название → описание или «-»)
│   ├── /update_role   — изменить роль (выбор роли → «Название» или «Описание»)
│   └── /delete_role   — удалить (юзеры → DefaultUser, чистит подключения)
│
├── 🔌 Подключения (Выводится текущая роль пользователя, видны все групповые подлкючения, созданные пользователями этой роли. Admin видит все подключения; в карточке — кто создал)
│   ├── /connections                — список (видимость по ролям, пагинация)
│   ├── /create_connection          — мастер (3 шага: имя → URL с проверкой подключения → роли видимости; «-» = все)
│   ├── /check_connection — тест подключения (SELECT 1); пошагово: ввод #id или имени
│   ├── /edit_connection — пошаговое изменение: название / URL (с проверкой) / роли видимости
│   ├── /activate_connection   — включить (пошагово: ввод #id → подтверждение)
│   └── /deactivate_connection — выключить (пошагово: ввод #id → подтверждение)
│
└── 🔔 Срабатывание триггера
    ├── личный → личка автору
    └── групповой → чат Telegram (chat_id в параметрах триггера)
```

**Правила доступа сейчас:**
- Роли: `Admin` (всё) и `DefaultUser` (базовые). Ролей у пользователя может быть несколько (`/add_role` добавляет к существующим).
- `DefaultUser` — стартовая роль при регистрации; снимается при добавлении любой другой; возвращается, когда забрали все роли.
- `Admin` — эксклюзивная роль (назначение Admin снимает прочие; забрать Admin нельзя).
- Видимость подключений: `allowed_roles` на подключении (пусто = роль создателя; «-» = все).
- Веб: войти может только пользователь, привязанный к Telegram (код из бота); деактивированный видит экран блокировки; права в вебе = правам в боте. Ссылку и порт задаёт секция `web:` в config.yaml.
- Меню: только основные команды (`show_in_menu: false` у служебных: create/update/delete_role, add_role, remove_role). В описаниях команд списков (triggers, connections, users, roles) динамически выводится текущая роль.
