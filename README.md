# ChatDB SelfService

Telegram-бот самообслуживания для аналитиков и разработчиков: самостоятельная
работа с подключениями к базам данных, триггерами на SQL-запросы и уведомлениями
о срабатываниях. К боту прилагается веб-интерфейс с теми же правами доступа.

Стек: Python 3.12+, SQLAlchemy (SQLite по умолчанию, поддерживаются любые
движки через `database_url`), python-telegram-bot (JobQueue), FastAPI/uvicorn
для веб-части.

## 1) Установка

1. Создайте и активируйте виртуальное окружение.
2. Установите зависимости:

```bash
pip install -r requirements.txt
```

3. Заполните `config.yaml` (скопируйте из `config.example.yaml`):
   токен бота, имя начального суперпользователя, `database_url`, список команд,
   секция `web:` (включённость, хост/порт веб-интерфейса).

Для подключения к PostgreSQL дополнительно ставится `psycopg2-binary`
(уже входит в `requirements.txt`).

## 2) Инициализация базы

```bash
python -m app.init_db
```

Команда:
- создаёт таблицы (`roles`, `users`, `user_roles`, `connections`, `triggers`);
- создаёт роли `Admin` и `DefaultUser`;
- создаёт суперпользователя из `initial_superuser_name` с ролью `Admin`.

Схема мигрируется автоматически при старте бота: недостающие колонки и таблицы
добавляются, исторические — переносятся (ручных миграций не требуется).

Тестовые данные (по желанию):
`python -m app.seed_test_users`, `python -m app.seed_test_connections`.

## 3) Запуск

```bash
python main.py
```

Запускает бота и вместе с ним веб-интерфейс (тот же процесс, та же БД):
http://127.0.0.1:8000 — хост/порт настраиваются секцией `web:` в `config.yaml`
(`enabled`, `host`, `port`, `public_url`).

Только веб, без бота: `python -m app.web` (расписания триггеров при этом
не тикают — их подхватит бот на следующем старте).

### Веб-интерфейс

- **Вход** — только через Telegram: команда `/weblogin` в боте присылает
  одноразовый код (5 минут), вводите его на странице входа. Телеграм остаётся
  точкой первого входа; без бота код получить нельзя.
- Дашборд (кто я, счётчики, ближайшие срабатывания), подключения, триггеры
  (создание/изменение одной формой, проверка, вкл/выкл, расписание на сутки),
  пользователи и роли — права те же, что в боте.
- Заблокированный пользователь видит экран блокировки.

## Архитектура

- **Пользователь** — участник системы, привязывается к Telegram-аккаунту
  при `/start` (по ФИО/username или создаётся с ролью `DefaultUser`).
- **Роль** — права и видимость. Ролей у пользователя может быть несколько;
  `DefaultUser` — стартовая (возвращается, если забрали все), `Admin` —
  эксклюзивная, видит всё и управляет всеми объектами. Управление ролями:
  `/roles`, `/create_role`, `/update_role`, `/delete_role`;
  назначение пользователю — `/add_role`, `/remove_role`.
- **Подключение (`Connection`)** — параметры доступа к БД (`database_url`).
  Видимость: пусто = роль создателя, `-` = все пользователи, список ролей =
  эти роли (любая роль пользователя из списка даёт доступ). Admin видит всё.
  В карточке видно, кто создал подключение.
- **Триггер (`Trigger`)** — SQL-запрос (SELECT, ровно 1 строка) + подключение +
  расписание + текст сообщения. Личный триггер шлёт результат автору в личку,
  групповой — в чат Telegram (`chat_id` или ссылка `https://t.me/c/<чат>/<топик>`
  — уведомление уйдёт в указанный топик). Планировщик: `every:5m`, `every:1h`,
  `daily:ЧЧ:ММ` (время местное, хранится в UTC) или только ручной запуск.
- **Параметры в сообщении**: `$1`, `$2`… подставляются из одноимённых
  столбцов запроса (`SELECT x AS "1", y AS "2"`); один столбец можно не именовать.

Полное дерево команд и правил видимости — [COMMANDS.md](COMMANDS.md).

## Команды бота (основные)

- `/start` — регистрация/вход, привязка Telegram-аккаунта (новичку — роль `DefaultUser`).
- `/whoami` — текущий пользователь и его роли.
- `/triggers` — список триггеров (личные + групповые своей роли; Admin — все).
- `/create_trigger` — пошаговое создание триггера.
- `/ping` — проверка, что бот жив.
- `/help` — список доступных команд.

Админские команды (`/users`, `/connections`, `/roles`, …) перечислены в
[COMMANDS.md](COMMANDS.md) и в подсказках под соответствующими списками.
